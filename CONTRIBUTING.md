# 🐛 Reportando bugs e sugerindo ideias

Encontrou um problema? Teve uma ideia? **Conte para a gente!** 💡

O GitHub possui um sistema chamado **Issues**, criado justamente para acompanhar problemas, sugestões e discussões relacionadas ao projeto.

Você pode utilizar as Issues para:

- 🐛 Relatar bugs.
- 💡 Sugerir novas funcionalidades.
- 🎨 Sugerir melhorias visuais.
- ⚡ Sugerir melhorias de desempenho.
- 📚 Sugerir melhorias na documentação.
- ❓ Fazer perguntas relacionadas ao desenvolvimento.
- 🔎 Relatar comportamentos inesperados.

### Antes de abrir uma Issue

Se possível:

1. 🔍 Procure nas Issues existentes para verificar se o problema ou sugestão já foi registrado.
2. 📝 Explique claramente o que aconteceu ou o que você gostaria de mudar.
3. 📱 Informe em qual dispositivo, navegador ou ambiente o problema aconteceu, quando isso for relevante.
4. 📸 Adicione capturas de tela ou outras informações úteis quando possível.
5. 🧩 Para bugs, explique como reproduzir o problema.

Quanto mais informações você fornecer, mais fácil será investigar e resolver a questão.

# 💻 Guia rápido para desenvolvedores

Quer contribuir diretamente com o código? Bora! 🚀

O fluxo básico de contribuição é:

**Fork → Branch → Commit → Pull Request**

## 1. 🍴 Faça um Fork

Crie uma cópia do repositório na sua própria conta do GitHub.

Depois, clone essa cópia para o seu computador.

## 2. 🌿 Crie uma Branch

Evite trabalhar diretamente na branch principal.

Crie uma branch específica para a alteração que você pretende fazer.

Procure utilizar nomes claros, por exemplo:

- `feature/player`
- `feature/categorias`
- `fix/menu-mobile`
- `fix/player`
- `docs/contributing`

O nome deve ajudar outras pessoas a entenderem o objetivo da branch.

## 3. 🛠️ Faça suas alterações

Agora é hora de colocar a mão no código! 💻

Antes de enviar sua contribuição:

- Verifique se o código funciona.
- Teste as alterações.
- Confira se não quebrou funcionalidades existentes.
- Mantenha o código organizado.
- Evite alterações que não estejam relacionadas ao objetivo da sua branch.

Se encontrar outro problema durante o desenvolvimento, considere abrir uma Issue para registrá-lo.

## 4. 📦 Faça o Commit

Quando sua alteração estiver pronta, faça um commit com uma mensagem clara.

Procure explicar **o que foi alterado**, em vez de usar mensagens genéricas como:

- `mudanças`
- `arrumei`
- `teste`
- `coisas`

Uma boa mensagem de commit facilita muito a manutenção do projeto no futuro. 🧭

## 5. 🚀 Abra um Pull Request

Envie suas alterações para o repositório original através de um **Pull Request (PR)**.

Na descrição do PR, explique:

- 📝 O que foi alterado.
- 🎯 Qual problema a alteração resolve.
- 💡 Qual foi a abordagem utilizada.
- 🧪 Como você testou a alteração.
- 🔗 Qual Issue está relacionada, caso exista.

Exemplo:

> Corrige o problema de layout do player em telas pequenas e melhora sua adaptação para dispositivos móveis.

Depois disso, outras pessoas poderão revisar sua contribuição, fazer perguntas e sugerir ajustes.

### 🔎 Durante a revisão

Não encare uma revisão como uma crítica pessoal.

Code review existe para melhorar o projeto e ajudar quem está contribuindo a aprender também. 🤝

Esteja aberto(a) a:

- Sugestões.
- Perguntas.
- Solicitações de alteração.
- Discussões técnicas.

Da mesma forma, quem revisar uma contribuição deve fazê-lo com respeito e buscando construir uma solução melhor.

# 🤝 Código de Conduta

A Rádio Geração Ativa é uma comunidade. Por isso, queremos que todas as pessoas possam participar em um ambiente seguro, respeitoso e colaborativo.

Esperamos que todos:

- ❤️ Tratem outras pessoas com respeito.
- 🤝 Sejam educados e colaborativos.
- 💬 Discordem de ideias sem atacar pessoas.
- 🧠 Estejam abertos a aprender e ensinar.
- 🌎 Respeitem diferentes experiências, opiniões e conhecimentos.
- 🛠️ Façam críticas de maneira construtiva.
- 🚫 Não pratiquem assédio, discriminação ou ataques pessoais.
- 🚫 Não publiquem conteúdo ofensivo ou inadequado.
- 🔐 Respeitem a privacidade das outras pessoas.
- 📚 Respeitem licenças, direitos autorais e atribuições de terceiros.

### 💡 Discordar faz parte

Projetos colaborativos naturalmente possuem opiniões diferentes.

Não precisamos concordar em tudo para trabalhar juntos. O importante é manter as discussões focadas no projeto, nos fatos e nas possíveis soluções.

**Ideias podem ser questionadas. Pessoas devem ser respeitadas.** ❤️
